# Bank REST API

Backend банковского приложения на Java и Spring Boot.

Проект реализован в виде Maven multi-module приложения и включает основной банковский сервис и отдельный сервис email-уведомлений.

Основная задача проекта — реализовать типичные банковские операции и показать применение современных backend-подходов: JWT-аутентификацию, PostgreSQL, Kafka, Transactional Outbox, идемпотентность обработки сообщений, Liquibase и интеграционное тестирование.

## Модули

### bank_cards_module

Основной банковский сервис.

Реализованы:

* регистрация и управление пользователями;
* JWT-аутентификация;
* авторизация по ролям `USER` и `ADMIN`;
* создание и получение банковских карт;
* блокировка и активация карт;
* заявки на операции с картами;
* переводы между картами;
* шифрование чувствительных данных карт;
* публикация бизнес-событий через Transactional Outbox.

### email_module

Отдельный сервис для обработки банковских событий и отправки email-уведомлений.

Реализованы:

* Kafka Consumer;
* обработка банковских событий;
* отправка email через SMTP;
* идемпотентная обработка сообщений;
* хранение обработанных `eventId` в PostgreSQL.

# Функциональность

## Пользователи

Пользователь содержит:

* `id`;
* `email`;
* имя;
* фамилию;
* роль;
* связанные банковские карты.

Email используется как username для аутентификации.

После регистрации создаётся событие `USER_REGISTERED`.

## Банковские карты

Реализованы операции:

* создание карты;
* получение информации о карте;
* блокировка карты;
* активация карты;
* создание заявок на блокировку и активацию;
* проверка владельца карты.

Номер карты хранится в зашифрованном виде и маскируется при выдаче через API.

Пример маскированного номера:

```text
**** **** **** 1234
```

## Переводы

Реализован перевод средств между банковскими картами.

Перед выполнением операции проверяются существование карт, принадлежность карт пользователю и наличие достаточного баланса.

После успешного перевода создаётся событие `TRANSFER_COMPLETED`.

# Transactional Outbox

Для надёжной публикации бизнес-событий используется Transactional Outbox.

Изменение бизнес-данных и сохранение события в таблицу `outbox_event` выполняются в рамках одной транзакции PostgreSQL.

Это позволяет избежать ситуации, когда бизнес-операция успешно сохранена в базе, но соответствующее Kafka-событие потеряно.

Отдельный Scheduled Publisher периодически выбирает новые события из Outbox и публикует их в Kafka.

Для конкурентной обработки записей используется:

```sql
FOR UPDATE SKIP LOCKED
```

Для событий предусмотрены статусы:

```text
NEW
PUBLISHED
FAILED
```

При ошибке публикации сохраняются количество попыток и информация о последней ошибке.

---

# Apache Kafka

Для обмена событиями между сервисами используется Apache Kafka.

Основной topic:

```text
bank-events
```

Тип события определяется полем `eventType`.

В проекте используются следующие события:

```text
USER_REGISTERED
CARD_CREATED
TRANSFER_COMPLETED
CARD_BLOCKED
CARD_ACTIVATED
```

`email_module` подписан на этот topic и обрабатывает события, для которых предусмотрены email-уведомления.

---

# Идемпотентность Consumer

Kafka consumer реализован с учётом возможности повторной доставки сообщений.

Для каждого события используется уникальный `eventId`.

В `email_module` существует таблица:

```text
processed_event
```

в которой сохраняются идентификаторы уже обработанных событий.

Перед обработкой consumer проверяет наличие `eventId`.

Если событие уже было обработано, повторная обработка пропускается.

Запись в `processed_event` выполняется после успешной отправки email. Поэтому при ошибке отправки сообщение может быть обработано повторно.

# Email Notifications

`email_module` отправляет уведомления по следующим событиям:

| Событие              | Уведомление               |
| -------------------- | ------------------------- |
| `USER_REGISTERED`    | подтверждение регистрации |
| `CARD_CREATED`       | создание банковской карты |
| `TRANSFER_COMPLETED` | выполнение перевода       |
| `CARD_ACTIVATED`     | активация карты           |
| `CARD_BLOCKED`       | блокировка карты          |

Для отправки используется `JavaMailSender` и SMTP.

Настройки SMTP передаются через конфигурацию приложения и переменные окружения.

Для тестирования используются:

* обработка ошибки Kafka;

# Запуск проекта

## Требования

Перед запуском необходимо установить:

* JDK 17+
* Maven
* PostgreSQL
* Apache Kafka
* Docker Desktop — для запуска тестов с Testcontainers

## Сборка

Из корня проекта:

```bash
mvn clean install
```

Без запуска тестов:

```bash
mvn clean install -DskipTests
```

## Запуск bank_cards_module

```bash
mvn spring-boot:run -pl bank_cards_module
```

## Запуск email_module

```bash
mvn spring-boot:run -pl email_module
```

Модули запускаются как отдельные Spring Boot приложения.
